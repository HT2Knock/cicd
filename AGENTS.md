# AGENTS.md — Notely (learn-cicd-starter)

A notes application ("Notely") from Boot.dev's "Learn CICD" course, forked by HT2Knock. This is a pedagogical project designed to teach CI/CD — the code is intentionally kept simple so the focus stays on the pipeline.

## Essential Commands

```sh
go build -o notely                     # local build
./scripts/buildprod.sh                 # production cross-compile (CGO_ENABLED=0 GOOS=linux GOARCH=amd64)
go test -v -cover ./...                # run all tests with coverage
go vet ./...                           # run go vet
golangci-lint run                      # lint (gosec, staticcheck, govet, gofmt)
sqlc generate                          # regenerate database code from SQL queries
```

- **Test**: `go test -v -cover ./...` (CI uses same command)
- **Run**: `go build -o notely && ./notely` (requires `PORT` env var; `DATABASE_URL` optional)
- **Deploy**: Triggered by push to `main` — see CD pipeline

## Architecture

### Module path
`github.com/bootdotdev/learn-cicd-starter` (original Boot.dev path — all imports use this)

### Layout

```
├── main.go                 # entrypoint, router setup, server start
├── handler_ready.go        # GET /v1/healthz
├── handler_user.go         # POST /v1/users, GET /v1/users
├── handler_notes.go        # GET /v1/notes, POST /v1/notes
├── middleware_auth.go      # ApiKey auth middleware
├── models.go               # domain types (User, Note) + DB→domain converters
├── json.go                 # respondWithJSON / respondWithError helpers
├── internal/
│   ├── auth/
│   │   ├── auth.go         # GetAPIKey() — extracts ApiKey from Authorization header
│   │   └── auth_test.go    # table-driven tests
│   └── database/           # sqlc-generated code (DO NOT EDIT)
│       ├── db.go           # Queries struct, New(), WithTx()
│       ├── models.go       # DB types (User, Note — all string fields)
│       ├── users.sql.go    # CreateUser, GetUser
│       └── notes.sql.go    # CreateNote, GetNote, GetNotesForUser
├── sql/
│   ├── schema/             # goose migrations (001_users.sql, 002_notes.sql)
│   └── queries/            # sqlc query definitions (users.sql, notes.sql)
├── static/index.html       # single-page frontend (embedded via //go:embed)
├── scripts/
│   ├── buildprod.sh        # cross-compile for prod
│   └── migrateup.sh        # run goose migrations against Turso
└── .github/workflows/
    ├── ci.yml              # runs on PR to main: test + lint
    └── cd.yml              # runs on push to main: test → lint → build → deploy
```

### Single main package
All handler code lives in `package main` at the root (no `/cmd/` directory). The only sub-packages are `internal/auth/` and `internal/database/`.

### Database is optional
If `DATABASE_URL` env var is not set, the server starts without CRUD endpoints. Only `GET /v1/healthz` and `GET /` work. This is checked at startup (`main.go:44-55`).

### Routes

| Method | Path | Auth | Handler |
|--------|------|------|---------|
| GET | `/` | No | Serves embedded `static/index.html` |
| GET | `/v1/healthz` | No | `{"status":"ok"}` |
| POST | `/v1/users` | No | Create user (returns API key) |
| GET | `/v1/users` | Yes | Get current user |
| GET | `/v1/notes` | Yes | List user's notes |
| POST | `/v1/notes` | Yes | Create a note |

### Control flow for authenticated requests

```
Request → chi router → middlewareAuth → auth.GetAPIKey() → DB.GetUser() → authedHandler(w, r, user)
```

## Key Patterns

### Two-layer model system
- **DB models** (`internal/database/models.go`): All fields are `string` (timestamps as RFC3339 strings, IDs as UUID strings). Generated by sqlc.
- **Domain models** (`models.go` in root): `time.Time` for timestamps, proper JSON tags. Converted via `databaseUserToUser()` / `databaseNoteToNote()` / `databasePostsToPosts()`.

### Handler type system
Two handler signatures:
- **Public**: `func(w http.ResponseWriter, r *http.Request)`
- **Authed**: `type authedHandler func(w http.ResponseWriter, r *http.Request, user database.User)` — wrapped via `middlewareAuth`

### API key auth
- Custom `ApiKey` scheme (NOT `Bearer`)
- Header: `Authorization: ApiKey <sha256-hex>`
- Key generation: `crypto/rand` (32 bytes) → `SHA256` → hex-encoded
- Parsed in `internal/auth/auth.go`

### Response helpers
- `respondWithJSON(w, code, payload)` — sets `Content-Type: application/json`
- `respondWithError(w, code, msg, logErr)` — logs the error, then responds with JSON error body. Logs 5XX responses additionally.

## Data layer

### Database
- **Engine**: SQLite via Turso/libsql
- **ORM**: None — raw SQL via sqlc v1.25.0
- **Migrations**: goose
- **Timestamps**: stored as TEXT in RFC3339 format (e.g. `2006-01-02T15:04:05Z07:00`)
- **IDs**: UUID v4, stored as TEXT

### sqlc workflow
1. Edit SQL in `sql/queries/`
2. Edit migrations in `sql/schema/`
3. Run `sqlc generate` to regenerate `internal/database/`
4. Schema + queries use SQLite syntax (`?` placeholders, not `$1`)

### Migrations
Run via goose: `cd sql/schema && goose turso $DATABASE_URL up`

## CI/CD Pipeline

### CI (PR to main)
1. `go test -v -cover ./...` (Go 1.26.0)
2. `golangci-lint` (v2.1, config in `.golangci.yml`)

### CD (push to main)
1. Tests + lint (same as CI)
2. `./scripts/buildprod.sh` — cross-compile binary
3. Google Cloud auth → `gcloud builds submit` to Artifact Registry
4. `./scripts/migrateup.sh` — run goose migrations
5. `gcloud run deploy` to Cloud Run

### Deployment details
- **GCP Project**: `notely-495210`
- **Artifact Registry**: `asia-southeast1-docker.pkg.dev/notely-495210/notely-ar-repo`
- **Cloud Run**: `us-central1`, `--allow-unauthenticated`, max 4 instances
- **Docker**: `debian:stable-slim` base with prebuilt binary (not multi-stage)

## Non-obvious Gotchas

- **Go version mismatch**: `go.mod` says `go 1.22` but CI uses `go 1.26.0`. When making changes, be careful with language features only available in newer Go versions.
- **sqlc generates `interface{}`**: The generated code uses `interface{}` not `any` (compatible with 1.22). Gopls will flag these but they shouldn't be edited manually.
- **`.golangci.yml` uses v2 config syntax**: Must use `version: "2"` with linters listed under `linters.enable`. This is the newer golangci-lint config format.
- **Mixed logging**: `json.go` uses `log.Println` and `log.Printf` while `main.go` uses `slog`. Error responses log via `log.Println(err)` but `respondWithJSON` failure uses `slog.Error`.
- **`.env` failures are non-fatal**: If `.env` can't be loaded, it logs a warning and continues with env vars from the environment.
- **`PORT` is required**: Unlike some frameworks that default to 8080, this app calls `log.Fatal` if `PORT` is unset.
- **CORS allows everything**: `AllowedOrigins: ["https://*", "http://*"]`, all methods, all headers.
- **CD region mismatch**: Image is built to `asia-southeast1` but deployed to `us-central1` (different continents). Not a bug per se, but unusual.
- **`.gcloudignore` only ignores `notely` binary**: Everything else gets uploaded.
- **No graceful shutdown**: Server uses `log.Fatal(srv.ListenAndServe())` with no `Shutdown()` call.
- **CI workflow file has a leading space**: The file content has a space prefix discrepancy (visible in git diff in the repo state). Be careful editing workflow YAML files.
- **Auth middleware uses `http.StatusNotFound` for unknown API keys** (line 22 of `middleware_auth.go`), not `401`. This is intentional.
- **The app is the entire `main` package**: Adding new Go files at root adds them to the same package. Use `internal/` for sub-packages.

## Tests

Only one test file exists: `internal/auth/auth_test.go`. Uses table-driven tests with `t.Run()` sub-tests. No integration or end-to-end tests.

When adding tests:
- Follow the table-driven pattern
- Test file location mirrors source (e.g., `internal/auth/auth_test.go` tests `internal/auth/auth.go`)
- Package name: `auth_test` (external test package)
